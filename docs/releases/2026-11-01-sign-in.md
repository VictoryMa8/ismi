The first release's health check kept seeing the prior revision. It automatically
restored the previous application and retained the database backup. Host lifecycle
logs later showed the provider applied restart several minutes after the request;
no startup exception was observed. The retry therefore used the same deployment
workflow with a ten-minute health window in a temporary operator helper.

The retry then stopped during staging extraction with **Disk quota exceeded**
(errno 122); physical free-space checks cannot detect the account quota. No live

its SQLite backup/manifest and all earlier releases were retained. The existing
verified retry archive was resumed, installed, restarted and fully checked.
No plan upgrade or spending was performed. Storage remains constrained; inspect
retained releases deliberately before another large upload.
